# ADR-0002. Монорепозиторий, независимые сервисы, Python + FastAPI + uv

Статус: предложено · 2026-09-19

## Контекст

В системе будет 4–5 сервисов, web-клиент и платформа качества (Quality Hub). Команда — один человек и AI-агент. Нужно тренировать межсервисные контракты, а это возможно, только если сервисы действительно независимы.

## Решение

1. Один репозиторий. Каждый сервис живёт в `services/<имя>` со своим `pyproject.toml`, lock-файлом, Dockerfile и тестами. Общего кода между сервисами нет: сервисы общаются только по сети.
2. Язык — Python 3.14, веб-фреймворк — FastAPI, управление зависимостями — uv с обязательным lock-файлом (`uv sync --locked`).
3. Версия Python одинакова локально, в CI и в образе (`.python-version`, базовый образ).

## Последствия

- Плюс: изменение контракта и обоих сервисов проходит одним PR. Позже можно запускать только тесты затронутых сервисов (выборочный запуск по путям).
- Плюс: FastAPI сам отдаёт OpenAPI-схему — основа для контрактных тестов в итерации 2.
- Цена: нельзя «просто импортировать» модель из соседнего сервиса. Это неудобство намеренное: именно оно заставляет описывать контракт явно.
- Цена: пайплайн со временем нужно научить понимать, какой сервис изменился.

## Альтернативы

- Репозиторий на сервис: ближе к большим компаниям, но для одного человека это накладные расходы без пользы для обучения.
- Модульный монолит: проще, но не на чем тренировать контракты и события.
