# ADR-0004. Бюджет времени обратной связи и Makefile как единственный источник команд

Статус: принято · 2026-09-19

## Контекст

Два типичных пути деградации пайплайна: он незаметно становится медленным, и команды в CI расходятся с тем, что разработчик запускает у себя («у меня работает»).

## Решение

1. У каждой задачи CI есть бюджет времени, заданный через `timeout-minutes`: проверки кода — 5 минут, стек и smoke — 10 минут. Превышение бюджета — это упавшая сборка, а не повод поднять лимит. Лимит меняется только новым ADR.
2. CI не содержит собственной логики. Он вызывает цели `make`, те же самые, что доступны локально: `make check`, `make up`, `make smoke`.
3. Пороги качества работают как храповик: покрытие (`fail_under`) только растёт; предупреждения в тестах считаются ошибками, известные чужие предупреждения перечислены поимённо.

## Последствия

- Плюс: бюджет времени — первая fitness function проекта: архитектурное свойство («быстрая обратная связь») проверяется автоматически.
- Плюс: любую красную сборку можно воспроизвести локально одной командой.
- Цена: в интерфейсе CI шаги выглядят как `make ...`, детали нужно смотреть в Makefile.
- Цена: жёсткий таймаут иногда будет ронять сборку из-за медленного раннера. Это сигнал, который мы хотим видеть, а не шум.

## Альтернативы

- Следить за временем «на глаз»: не работает, деградация по 10 секунд незаметна.
- Логика в YAML пайплайна: привязывает к GitHub и не запускается локально.
