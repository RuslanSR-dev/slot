# ADR-0011. Клиент WireMock остаётся скопированным в каждый сервис

Статус: принято · 2026-09-20

## Контекст

В «Долгах» с итерации 2 записано правило: клиент WireMock скопирован в тесты каждого сервиса, и при появлении третьей копии решение нужно оформить через ADR. В итерации 3 появился `notifier`, а с ним третья копия `tests/component/wiremock.py` (около 60 строк). Правило сработало — пора решать.

Рядом есть ещё две «почти копии»: помощник `wait_until` (4 строки, в трёх сервисах и в smoke) и фикстуры Postgres/Redis в `conftest.py`.

## Варианты

| Вариант | Плюсы | Цена |
|---|---|---|
| **Оставить копии** | Сервисы остаются независимыми: тесты одного нельзя сломать изменением в чужом файле. Ноль инфраструктуры | Правка в трёх местах, если менять всерьёз. Копии могут разойтись |
| **Общий пакет `testkit`** | Одна правка вместо трёх, одно место для новых помощников | Четвёртый проект: свой `pyproject.toml`, свой lock-файл, свои gates, версионирование. Любое его изменение обязано перезапускать component-тесты всех сервисов — анализ влияния из итерации 2b придётся учить этому. Тесты сервисов перестают быть самодостаточными |
| **Шаблон (cookiecutter) для нового сервиса** | Копии осознанные, старт нового сервиса дешевле | Копии всё равно расходятся, а шаблон — ещё одна вещь, которую нужно поддерживать в актуальном состоянии |

## Решение

**Копии остаются.** Общий пакет не заводим.

Правило трёх — про три **изменения**, а не про три копии. За две итерации `wiremock.py` не менялся ни разу: он повторяет чужой стабильный API. Платить за это четвёртым проектом с собственным жизненным циклом дороже, чем скопировать файл.

Плюс важное следствие ADR-0002: сервисы должны выкатываться независимо. Общий код в тестах не мешает выкатке, но мешает другому — изолированности обратной связи. Сегодня «упал component-тест `payments`» означает «сломан `payments`». С общим пакетом это будет означать «сломан `payments` или `testkit`», и разбирать придётся каждый раз.

Условия пересмотра (любое достаточно):

1. один и тот же содержательный правок приходится делать в трёх копиях одновременно;
2. копии разошлись, и из-за этого тесты сервисов проверяют разное, не желая того;
3. общих помощников становится больше трёх файлов.

Чтобы расхождение было видно, в каждом скопированном файле стоит комментарий «дублируется намеренно», а в `test-strategy.md` — правило 20.

## Последствия

- Плюс: новый сервис начинается с копирования двух файлов и ничего не должен знать про общий пакет.
- Плюс: анализ влияния остаётся простым — у каждого файла ровно один владелец-сервис.
- Цена: правка клиента WireMock — это три одинаковых правки. Принято сознательно, с записанным условием пересмотра.
- Цена: копии могут разойтись незаметно. Это не проверяется автоматически; если станет проблемой, сработает условие 2.
