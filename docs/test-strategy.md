# Стратегия тестирования, версия 1

Документ живой: каждая итерация добавляет в него уровень или правило.

## Уровни тестов

Определения заданы через границу, а не через название. Большая часть споров про «unit против integration» — это споры о разных определениях.

| Уровень | Что запущено | Что заменено | Где лежит | Статус |
|---|---|---|---|---|
| unit | Код сервиса в процессе теста | Сеть, база, время | `tests/unit` | есть |
| component | Один сервис + его настоящий Postgres в контейнере (Testcontainers) | Соседние сервисы и внешние API — заглушки; время — управляемые часы | `tests/component` | есть |
| contract | Ожидания потребителя против схемы поставщика | Всё остальное | `tests/contract` | итерация 2 |
| smoke | Весь стек из `compose.yaml` | Только внешние системы | `tests/smoke` | есть |

e2e через интерфейс — только критические сценарии, единицы штук. Всё, что можно проверить уровнем ниже, проверяется уровнем ниже.

## Какой риск каким уровнем закрыт

| Риск | Уровень | Почему именно там |
|---|---|---|
| Недопустимый переход статуса брони, слот в прошлом, некорректный слот | unit | Чистая логика без базы; все комбинации перебираются за миллисекунды |
| Два клиента одновременно заняли один слот | component, тест на гонку | Гонку видно только на настоящей базе и при одновременных запросах (ADR-0005) |
| Ответы API: коды, ошибки, фильтры | component | Нужна настоящая база: коды `409` рождаются из её ограничений |
| Бронирование в момент начала слота | component, управляемые часы | Время двигает тест, а не реальность |
| Забыли миграцию; миграция не откатывается | component, тесты миграций | Миграции — код, который в проде запускается один раз и без права на ошибку |
| Условие индекса разошлось с `ACTIVE_STATUSES` в коде | component, отдельный тест | Alembic не сравнивает условия индексов |
| Образ не собирается, миграции не применились, сервис не видит базу | smoke | Проверяется только на собранном стеке |
| Запущена не та сборка | smoke | ADR-0003 |

## Quality gates в пайплайне

| Gate | Задача CI | Порог | Зачем |
|---|---|---|---|
| Форматирование и линтер (ruff, включая правила безопасности `S`) | checks | 0 нарушений | Ревью человека — про смысл, а не про стиль |
| Строгая типизация (mypy strict) | checks | 0 ошибок | Детерминированная проверка AI-кода до запуска |
| Unit-тесты | checks | все зелёные | Быстрая обратная связь без Docker |
| Component-тесты | component | все зелёные | Поведение на настоящей базе |
| Покрытие (unit + component) | component | не ниже 90%, только растёт | Храповик, а не цель (ADR-0006) |
| Предупреждения в тестах | все | считаются ошибками | Устаревшие вызовы ловим в день появления |
| Smoke на эфемерном стеке | stack-smoke | все зелёные, версия сборки совпадает | Образ собирается, стартует и это именно он |
| Время задач CI | все | checks 5, component 8, stack-smoke 10 минут | ADR-0004, ADR-0006 |

## Правила

1. Никаких `sleep` в тестах: ждём условие с таймаутом (`wait_until` в `tests/component/conftest.py`).
2. Повторный запуск упавшего теста — это сигнал для учёта flaky, а не способ получить зелёную сборку.
3. Тест не «лечится» автоматически. Любое изменение ожиданий теста проходит ревью человеком.
4. Порог можно ослабить только через ADR.
5. Smoke-тесты знают только URL. Тот же файл потом проверяет развёрнутый стенд, поэтому smoke создаёт уникальные данные и не рассчитывает на пустую базу.
6. Код не читает часы сам: время передаётся параметром `now`. Тест управляет временем через `FixedClock`.
7. Component-тесты используют тот же образ Postgres, что и стек. Тест на подмене базы (SQLite, моки) не доказывает поведение ограничений и конкуренции.
8. Каждый тест component-уровня начинает с пустых таблиц. Порядок тестов не важен.
9. Тест на гонку повторяет гонку несколько раундов в одном прогоне: один раунд может её не поймать.

## Что сознательно отложено

- Mutation testing доменного модуля — следующий шаг итерации 1.
- Производительность, сканеры безопасности, трассировка — итерация 6.
- Проверка готовности сервиса к работе с базой (`/ready` в отличие от `/health`) — записано в «Долги и находки».
